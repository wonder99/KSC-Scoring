Before you begin

Open /admin and enter the ADMIN_API_KEY configured on the server. Successful login creates a 12-hour HttpOnly session cookie. The key is cleared from form fields and is not stored in browser session storage or source files.

Teams, players, matches, submissions, and reports use the selected season. Keep exactly one season marked active for public report defaults and player submissions.

Seasons

  • Add a season by name, start date, and optional end date.
  • Mark only the current season active.
  • The 2026-2027 baseline is preserved through Week 10, ending November 18. Submissions for Week 10 or earlier are blocked.

Teams

  • Add a team by entering its display name.
  • Each team card shows the team name and active-season player count.
  • Roster limits are not used.
  • Delete a team only when it has no active season or schedule dependencies.

Players

Player cards are compact and ordered by team, player name, gender, and actions.

  • Add: enter first name, optional last name, gender, season, and team.
  • Edit: use the edit form to correct first name, last name, or gender. The existing player ID is preserved, so linked baselines and turn history remain with the person.
  • Remove from roster: remove the player from the selected season only. The player record and historical database links remain available.
  • Merge: enter the canonical player ID to keep. All roster, baseline, turn, lineup, and finish references for the duplicate move to that record.
  • Delete player: delete the whole player record. Use Remove from roster or Merge instead when historical stats or submissions exist.

Schedule

  • Add a match with season, week, date, board, home team, and away team.
  • Schedule rows show Week, date/board, and both team names in one compact line.
  • Edit changes week, date, board, or team IDs.
  • Delete a match only after reviewing linked games and submissions.

Score Uploads

  • Review turns: opens normalized turn rows and lets the organizer revise a score with a required reason.
  • Accept: include an accepted submission in public reports.
  • Reject: remove that submission from public reports while preserving the audit record.
  • A repeated browser or CSV submission supersedes earlier accepted data for the same match game.

Reports

Public stats at /stats combine preserved workbook baselines with accepted submissions after Week 10. Report categories include standings, mens/ladies overall statistics, averages, 95+, outs, and leaders.

Stat reports do not cap the number of players. 95+ and outs report views include only qualifying players.

Destructive operations

Deleting a team, player, match, or submission can affect linked historical data. Prefer removing a player from a roster or rejecting a submission unless permanent deletion is necessary.

Merging duplicates requires confirming a canonical player ID. Verify the ID and name before confirming.

Backups and restore

The Backups tab can create a custom-format PostgreSQL backup and download it to the administrator's computer. Restore the database only after choosing a listed backup and typing RESTORE exactly.

Use Upload Backup to restore a lost backup file to the server. Uploading is only file recovery; it does not change the database. Download or restore the uploaded file from the backup list afterward.

Web backup and restore require pg_dump and pg_restore to be installed in the Node server environment and available on PATH.

Create a backup from a server terminal with npm.cmd run backup. Backups are custom-format PostgreSQL dumps stored in backups/.

Before restoring, stop the app and confirm that DATABASE_URL points to the intended target database. Restore with:

npm.cmd run restore -- --confirm=RESTORE --file=backups\league-file.dump

The restore command removes existing objects before restoring the dump. It is intentionally blocked unless --confirm=RESTORE is supplied.

If restore reports that the server is not the owner of the pg_stat_statements extension and lists exactly two ignored extension operations, this is treated as a warning and the restore can still complete. Other restore errors remain failures and require review.
